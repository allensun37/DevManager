# DevManager v0.8 In-Flight Graceful Shutdown Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prove that a real authenticated in-flight HTTP request drains safely during shutdown, while new connections are rejected and a timeout retains its failure result without unsafe thread termination.

**Architecture:** Keep the lifecycle coordination in the application layer and the request-control seam in the HTTP adapter. `ServiceLifecycle` retains the shutdown result and gains a bounded responsibility to finish a timeout shutdown after the runtime really drains. `HttpServer` owns an optional shared test hook, publishes a post-`server.stop()` accepting-stopped boundary, and relies on cpp-httplib's completed listener return for worker drain and safe listener join.

**Tech Stack:** C++17, CMake, CTest, GoogleTest 1.17.0, cpp-httplib, spdlog, nlohmann/json, GitHub Actions Ubuntu and Windows.

## Fixed implementation contracts

`HttpServerTestHook` is an HTTP-layer abstract interface with exactly `virtual void onAuthenticatedRequest() noexcept = 0`. It is supplied as `std::shared_ptr<HttpServerTestHook>` only through optional `HttpServer` constructor parameters; all production call sites keep the default `nullptr`. `HttpServer` retains a shared reference while workers can use it. Its test implementation reports entry and blocks/releases with `std::mutex` and `std::condition_variable`; it performs no GoogleTest assertion and throws no exception from the HTTP worker.

The hook runs only after a protected request has passed the existing API-key authenticator and before the pre-routing handler returns `Unhandled` to `ProjectHttpController`. The in-flight test uses only `GET /api/projects` with `Authorization: Bearer test-key`.

`HttpServer::stopAccepting()` remains synchronous: after its `server_.stop()` call returns it publishes `acceptingStopped_ = true` and notifies a condition variable. `waitUntilAcceptingStopped(timeout)` waits for that post-stop publication. It does not wait for the listener thread, because that thread may correctly remain alive while the blocked request drains.

For this adapter, `drained` means `listen_after_bind()` has returned, all already-entered HTTP handlers have ended as part of cpp-httplib shutdown, and the owned listener thread has been joined. `waitUntilDrained()` returns true only after that join.

On a drain deadline timeout, `ServiceLifecycle::stopWhenRequested()` returns and retains `ServiceExit::ShutdownTimeout` while `ReadinessState` remains `Stopping`. Add `finishAfterDrain()` to wait indefinitely for the same runtime after the test releases work, mark Readiness `Stopped`, and return the unchanged `ShutdownTimeout`. This method is a no-op for `Stopped`, `ForceStopRequested`, `Failed`, and `NoStopRequested`; it never converts a prior timeout into success.

ServiceExit ServiceLifecycle::finishAfterDrain() {

In `ServiceLifecycleIntegrationTests.cpp`, add a test-only hook:

```cpp
class BlockingAuthenticatedRequestHook final : public devmanager::HttpServerTestHook {
public:
    void onAuthenticatedRequest() noexcept override {
        std::unique_lock<std::mutex> lock(mutex_);
        entered_ = true;
        enteredCondition_.notify_all();
        releasedCondition_.wait(lock, [this]() { return released_; });
    }

    [[nodiscard]] bool waitUntilEntered(std::chrono::milliseconds timeout) {
        std::unique_lock<std::mutex> lock(mutex_);
        return enteredCondition_.wait_for(lock, timeout, [this]() { return entered_; });
    }

    void release() noexcept {
        std::lock_guard<std::mutex> lock(mutex_);
        released_ = true;
        releasedCondition_.notify_all();
    }

private:
    std::mutex mutex_;
    std::condition_variable enteredCondition_;
    std::condition_variable releasedCondition_;
    bool entered_ {false};
    bool released_ {false};
};
```

Add a scope guard whose destructor calls `hook->release()` so any failed assertion cannot leave a worker blocked. Add both complete real-server tests described below: the normal-drain case and the 20 ms timeout-safe-cleanup case. They construct `HttpServer` with a `std::shared_ptr<BlockingAuthenticatedRequestHook>` and call both `server.waitUntilAcceptingStopped(...)` and `lifecycle.finishAfterDrain()`; compilation must fail before implementation because these APIs do not exist.

Use this cleanup helper before starting either request thread:

```cpp
class RequestThreadCleanup final {
public:
    RequestThreadCleanup(std::shared_ptr<BlockingAuthenticatedRequestHook> hook,
                         std::thread& request,
                         std::thread& coordinator)
        : hook_(std::move(hook)), request_(request), coordinator_(coordinator) {}

    ~RequestThreadCleanup() {
        hook_->release();
        if (coordinator_.joinable()) {
            coordinator_.join();
        }
        if (request_.joinable()) {
            request_.join();
        }
    }

private:
    std::shared_ptr<BlockingAuthenticatedRequestHook> hook_;
    std::thread& request_;
    std::thread& coordinator_;
};
```
