# DevManager v0.3 HTTP 服务设计

状态：设计已根据评审意见修订，尚未开始编码。

## 目标

在 v0.2 命令行版本的基础上增加一个本地 HTTP 接口，使现有项目管理能力可以通过 REST/JSON 调用。v0.3 不改变现有业务规则，不引入数据库、Redis、Docker、前端、认证、日志系统或配置系统。

## 范围

HTTP 只暴露 v0.2 已有能力：

- 新增、编辑和删除项目；
- 列出项目；
- 按名称或技术栈搜索；
- 按状态筛选；
- 按 ID、名称或状态升序排序。

以下内容明确不在范围内：

- 单项目查询接口；
- PATCH 局部编辑；
- 多条件组合筛选；
- 分页、用户系统、Token 认证、授权和 API 版本化；
- HTTPS、文件上传、WebSocket、OpenAPI 自动生成和前端页面；
- 数据库、Redis、Docker、日志系统和配置中心。

## 分层架构

```text
devmanager_http
    └── HttpServer
          └── ProjectHttpController
                └── ProjectManager
                      └── ProjectRepository
                            └── JsonProjectRepository
```

HTTP 只作为传输适配层。`ProjectManager`、`ProjectRepository`、`JsonProjectRepository` 和 `MenuController` 的业务职责保持不变；HTTP 类型、请求 JSON 和响应 JSON 不进入业务层。

### 目录规划

```text
include/
  http/
    HttpServer.h
    ProjectHttpController.h
    ProjectHttpJsonMapper.h
    HttpError.h

src/
  http/
    HttpServer.cpp
    ProjectHttpController.cpp
    ProjectHttpJsonMapper.cpp
  http_main.cpp

tests/
  http/
    ProjectHttpJsonMapperTests.cpp
    ProjectHttpControllerTests.cpp
    HttpServerIntegrationTests.cpp
```

`HttpError` 和 `ProjectHttpJsonMapper` 都属于 HTTP 层。它们不是未来技术的通用抽象：前者只构造 HTTP 错误响应，后者只处理项目 HTTP 请求/响应字段。

### HttpServer

`HttpServer` 是 HTTP 传输适配器，负责：

- 持有并配置 `cpp-httplib::Server`；
- 注册项目路由；
- 绑定地址和端口；
- 启动阻塞运行；
- 提供可测试的停止能力和实际绑定端口。

它不实现项目业务规则，也不直接操作仓储。

### ProjectHttpController

`ProjectHttpController` 负责：

- 读取路径、查询参数和请求 JSON；
- 调用 common 层的 `ProjectIdParser` 严格解析项目 ID；
- 将请求字段转换为 `ProjectManager` 参数；
- 调用 `ProjectManager` 的现有接口；
- 通过 `ProjectHttpJsonMapper` 转换项目数据；
- 将返回值和异常映射为 HTTP 状态码和错误码。

Controller 不把不存在项目改造成新的领域异常：`ProjectManager::updateProject()` 和 `deleteProject()` 返回 `false` 时，由 Controller 映射为 `404 project_not_found`。

### HttpError

`HttpError` 只作为 HTTP 层的错误值/响应构造工具，负责生成统一的 JSON 错误体。它不定义 `ProjectNotFoundException`，不修改 `ProjectManager` 的返回值和异常类型，也不暴露底层异常堆栈。

### ProjectHttpJsonMapper

`ProjectHttpJsonMapper` 是一个聚焦的 HTTP JSON 转换组件：

- 将 `Project` 转换为 HTTP 响应对象；
- 解析新增/编辑请求的字段；
- 校验字段存在性、类型和禁止字段；
- 不负责持久化 JSON 文件格式。

现有 `Project::toJson()`/`fromJson()` 继续服务于 Repository，不在本阶段删除或重构。

## HTTP 可执行目标

保留现有 `DevManager` 循环菜单程序，新增独立的 `devmanager_http` 可执行文件：

- `src/main.cpp`：CLI 入口；
- `src/http_main.cpp`：HTTP 入口。

两个入口共享 domain、application 和 repository 库，但彼此不依赖。HTTP 入口默认构造 `JsonProjectRepository("data/projects.json")` 和 `ProjectManager`，然后启动 `HttpServer`。加载失败时由入口捕获异常并以非零状态退出。

## 路由契约

### 列表、搜索、筛选和排序

```text
GET /api/projects
```

支持的查询参数：

- `name`：按名称搜索；
- `technology`：按技术栈搜索；
- `status`：按状态筛选；
- `sort=id|name|status`：升序排序。

`name`、`technology`、`status` 最多出现一个；`sort` 可以和其中一个条件同时出现，也可以单独出现。没有筛选条件但指定 `sort` 时，返回完整项目列表的排序结果。

重复的筛选/排序参数和未知查询参数返回 `400 invalid_query`。查询参数的空白和大小写处理继续由现有 `AsciiText` 与 `ProjectManager` 规则负责，HTTP 层不复制业务匹配逻辑。

### 新增项目

```text
POST /api/projects
```

请求必须使用 JSON 内容类型，正文为：

```json
{
  "name": "DevManager",
  "techStack": ["C++", "CMake"],
  "description": "项目管理工具",
  "status": "active"
}
```

客户端不得提供 `id`；未知字段按 `400 invalid_request` 处理。ID 由 `ProjectManager` 生成，并继续遵守不复用和溢出规则。成功返回 `201 Created` 和完整项目对象。

### 编辑项目

```text
PUT /api/projects/{id}
```

请求必须使用 JSON 内容类型，并包含 `name`、`techStack`、`description` 和 `status`。路径中的 ID 是唯一 ID 来源；请求体中的 `id` 或未知字段按 `400 invalid_request` 处理。

成功返回 `200 OK` 和更新后的完整项目对象。项目不存在返回 `404 project_not_found`。

### 删除项目

```text
DELETE /api/projects/{id}
```

成功返回 `204 No Content`。项目不存在返回 `404 project_not_found`。删除确认只属于 CLI 交互，HTTP 不模拟 y/Y 确认。

## JSON 格式

项目对象沿用现有字段名和类型：

```json
{
  "id": 1,
  "name": "DevManager",
  "techStack": ["C++", "CMake"],
  "description": "项目管理工具",
  "status": "active"
}
```

- `id` 为正整数；
- `techStack` 为非空字符串数组；
- `name` 和 `status` 不得为空白；
- `description` 可以为空。

成功响应不使用额外 `data` 包装：列表直接返回数组，新增和编辑直接返回项目对象，删除返回空响应。

## 错误契约

所有错误返回 JSON：

```json
{
  "error": {
    "code": "project_not_found",
    "message": "项目不存在"
  }
}
```

状态码和错误码：

| 状态码 | 错误码 | 场景 |
|---|---|---|
| 400 | `invalid_json` | 请求体不是合法 JSON |
| 400 | `invalid_request` | 字段缺失、类型错误、未知字段或项目校验失败 |
| 400 | `invalid_id` | ID 不是正整数或发生溢出 |
| 400 | `invalid_query` | 查询参数重复、组合或排序键非法 |
| 404 | `project_not_found` | 目标项目不存在 |
| 409 | `id_exhausted` | `nextId == UINT64_MAX`，拒绝新增且状态不变 |
| 500 | `persistence_failure` | 保存、替换或其他仓储操作失败 |
| 500 | `internal_error` | 未预期的内部错误 |

不向客户端暴露底层堆栈和文件系统细节；服务端保留现有异常处理行为，不新增日志系统。

## ID 解析

将现有菜单中的严格 ID 解析逻辑抽取为纯 common 组件 `ProjectIdParser`，由 CLI 和 HTTP 共用。它必须拒绝：

- 空字符串；
- `0`；
- `+1`、负数和带符号文本；
- 非十进制字符和尾随字符；
- 超出 `ProjectId` 范围的数值。

HTTP 层只负责把解析失败映射为 `400 invalid_id`，不把解析逻辑放入 `ProjectManager`。

## 运行与并发约束

- 默认监听 `127.0.0.1:8080`，只允许本机访问；
- HTTP 与 CLI 复用 `data/projects.json`；
- 同一数据文件不支持 CLI 与 HTTP 的并发写入，README 必须明确说明；
- 同一个 HTTP 进程内，所有对 `ProjectManager` 的调用由 HTTP 层互斥保护，保证读写不会同时访问可变状态；
- 服务主线程阻塞运行；
- 测试环境允许绑定动态端口，绑定完成后可查询实际端口；
- `HttpServer::stop()` 可以安全结束测试服务，不增加复杂信号管理或后台守护功能。

## 依赖和构建

- 保持 C++17；
- 使用 `cpp-httplib` 提供 HTTP 服务和测试客户端；
- 通过 CMake 管理依赖，并固定明确的版本或提交；
- v0.3 不启用 HTTPS/OpenSSL；
- 新增 HTTP 库目标、HTTP 可执行目标和 HTTP 测试目标；
- 原 CLI、现有测试和双平台 CI 行为保持不变。

## 测试设计

测试分为纯组件测试和 HTTP 集成测试：

### 纯组件测试

- `ProjectIdParser`：空值、符号、非数字、尾随字符和溢出；
- `ProjectHttpJsonMapper`：字段缺失、类型错误、禁止 `id`、未知字段和项目字段转换；
- 查询参数解析：筛选条件互斥、`sort` 单独使用、重复参数和未知参数；
- `HttpError`：状态码、错误码和 JSON 结构。

### HTTP 集成测试

- 测试线程启动 `HttpServer`；
- 绑定 `127.0.0.1` 动态端口；
- 使用 `httplib::Client` 发送真实 HTTP 请求；
- 测试结束调用 `stop()`；
- 每个测试使用独立临时数据目录或失败注入仓储，不依赖文件权限。

至少覆盖：

- 列表、名称搜索、技术栈搜索、状态筛选和三种排序；
- 仅使用 `sort` 的完整列表查询；
- 新增成功、字段校验失败、ID 自动生成和 ID 溢出；
- 编辑成功、保留 ID 和不存在 ID；
- 删除成功和不存在 ID；
- 非法 JSON、缺失字段、错误类型、未知字段、非法 ID 和非法查询组合；
- 仓储保存失败映射为 `500`，且 ProjectManager 回滚规则保持成立；
- 多个并发请求不会造成重复 ID 或丢失项目；
- 服务可启动、可处理请求并可通过 `stop()` 结束。

## 分阶段实现边界

实现时按以下顺序拆分，并在每阶段先写失败测试：

1. **共享解析工具与 HTTP 依赖**：抽取 `ProjectIdParser`，加入 `cpp-httplib` 和 HTTP CMake 目标；
2. **JSON 映射与错误响应**：实现 `ProjectHttpJsonMapper`、`HttpError` 和纯组件测试；
3. **HttpServer 生命周期**：实现绑定、动态端口、停止和 HTTP 层互斥保护；
4. **查询路由**：实现列表、搜索、筛选、排序和查询参数校验；
5. **写入路由**：实现新增、编辑、删除、错误映射和持久化失败回滚；
6. **HTTP 入口和集成测试**：新增 `src/http_main.cpp`、独立可执行目标和回环集成测试；
7. **文档与发布检查**：更新 README、非目标/并发说明、构建说明和 v0.3 版本信息。

每阶段完成标准为：目标范围内测试通过、未越过分层边界、现有 CLI 测试保持通过，并在 Windows 与 Ubuntu CI 上成功构建和运行测试。
